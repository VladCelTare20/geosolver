# ag-studio/assets — the web pages, compiled into the binary

Up: [../../CODEMAP.md](../../CODEMAP.md) · Server: [../src/](../src/CODEMAP.md)

## Files
- `index.html` + `app.js` — the solver app (`/app`, or `/` in guest mode): history rail, composer, verdict, statement, steps, figure.
- `landing.html` + `landing.js` — the signed-out home page; its showcase is `showcase.json`, a real `/api/solve` answer (IMO 2023 P2, shortest-proof mode).
- `auth.html` + `auth.js` — sign in / create account.
- `gate.html` — the shared-password page, a template `gate.rs` fills (`{{…}}`, HTML-escaped i18n strings); no script at all, so it works with JS off and needs no CSP hash. Served with the public files listed in `security.rs:PUBLIC_PATHS` (`app.css`, fonts, icons).
- `site.js` — shared by all pages: icons, theme menu, math typesetting (`GS.math`), typed facts (`GS.fact`), step list (`GS.renderSteps`), human-style proof (`GS.renderHuman`, `GS.humanText`), figure viewer (`GS.Viewer`).
- `i18n.js` — EN/RO catalogue and the `data-i18n*` markup engine; plurals via `tp(key, n)` with `.one/.few/.other`.
- `app.css` — the design system (tokens, components) and the app layout; landing/auth add small page-local `<style>` blocks.
- `fonts/` — Inter and STIX Two Text as woff2 subsets (Latin, Latin Ext-A incl. Romanian, Greek, math symbols), both SIL OFL 1.1 (see `fonts/LICENSES.md`). The `.ttf` files are renamed static instances ("GeoSolver Sans", "GeoSolver Math", with math symbols added from DejaVu) used only by the server's PDF/PNG reports; DejaVu TTFs are the last fallback.

## Notes
- Page heads — every page links `/manifest.webmanifest`, `/favicon.svg`, `/apple-touch-icon.png`, the `apple-mobile-web-app-*` metas (status bar `default`: `black-translucent` forces white status-bar text over the light header) and two `theme-color` metas split by `prefers-color-scheme`; `<!--pwa-splash-->` is replaced by the launch-image links at startup (`pwa.rs:with_splash`).
- `site.js:applyTheme` — an explicit light/dark choice sets both `theme-color` metas to that colour; "system" restores light `#f7f7f5` / dark `#121417` so the media attributes decide.
- `site.js:isGate` / `toGate` — a 401 with `code: "gate"` (the shared password is gone, not the account session) goes to `/gate?next=<this page>`; `app.js:api`, `auth.js` and the export path return a never-settling promise then, so no error flashes. `landing.js` treats any 401 on `showcase.json` the same way.
- `app.js:authLost` — other 401s end the *account* session only when `S.status.signed_in`; a guest is never told "your session has ended". A 401 `code: "sign_in"` (guest AI off) shows the server's sentence with Sign in.
- `app.js:paintAiPill` — paints the header pill (`#ai-pill`, ≥ 768 px) and the composer pill (`#ai-pill-m`, phones), so a phone shows whether AI is on without opening Describe; the header has no room for it at 320–430 px in Romanian. On coarse pointers tapping either pill toasts its explanation. The `sign_in` gate offers Sign in and Create account.
- `i18n.js:current` — saved choice, else the `lang` cookie, else the first `ro`/`en` in `navigator.languages`, else English (the head snippet does the same for the no-flash class); the cookie is rewritten on load only for a saved choice, so the server's `Accept-Language` reading is not overridden by a default.
- `index.html` footer — "Forget this device" is a plain `POST /gate/forget` form, shown when `/api/status` says `gate: "cookie"`.
- Every inline `<script>` is pinned by hash in the CSP (`security.rs:content_security_policy`, computed from these files at startup); page logic lives in the `.js` files, which `'self'` allows. Only the tiny theme/language no-flash snippet in each `<head>` is inline.
- `site.js:Viewer` — zoom changes the SVG `viewBox` (crisp at any scale); labels and dots are re-sized per zoom from `data-x/y/dx/dy` so they stay a constant screen size.
- `site.js:Viewer.highlight(points, facts)` — with facts (steps, GIVEN, PROVE) only the objects the predicate names light up (`factShape`): cyclic → its circle, simtri → six sides, perp/para/cong → two segments, eqangle → the arms and the arc at the vertex, coll → its line; a drawn line is lit when it contains one of those segments. Facts it cannot read (prose, formulas) fall back to points: a line with ≥ 2 of them, a circle with ≥ 3 (or its centre + 2), marks when all of theirs are.
- `app.js:solve` — a new solve clears the previous result before anything else, so an error can never sit next to an old verdict. "Shortest proof" shows the standard result first, then swaps in the best-mode proof only if it is strictly shorter.
- `app.js:deleteHistory` — deletion is deferred 6 s for Undo; pending deletes are flushed with `keepalive` on `pagehide`.
- Colour tokens were checked for WCAG AA (text ≥ 4.5:1, borders/graphics ≥ 3:1) in both themes.
- `site.js:modal` — full-screen figure and the history drawer: everything outside is `inert`, the element becomes `role=dialog aria-modal=true`, Tab wraps inside, and closing restores exactly what was made inert.
- `site.js:renderSteps` — roving tabindex on steps; `hooks.describedBy` points every step at a visible "↑ ↓ move between steps" hint (`proof.kbd`, hidden on coarse pointers; the statement's facts use `st-kbd` the same way). The fold toggle is named "Show/Hide steps 1–8, 10" (`proof.hyps.*_sr`); a step's cites are tab stops only while that step is active; a `focusout` that leaves the list clears the highlight. Steps of kind `given` (restated hypotheses) are folded into one "Steps 1–8, 10 restate …" row with Show/Hide; they stay in the list hidden (`data-restated`), and a cite to one unfolds them. `subs` render as a bordered list under the step. `.step-meta` is a wrapping flex row: the rule and `←` are one flex item (it moves to the next line whole, and wraps inside only when wider than a line; the arrow is glued to the rule's last word), the cite chips their own wrapping box (`.cites`), so chips that wrap line up under the first chip.
- `site.js:math` — prose tokens split at `·` and `/`, and `sin∠ABC` / `△ABC` italicise the point run, so trig steps use the same type as the facts.
- `site.js:placeLabels` — at a label scale above the server's (`k` > 1 in a small panel or the hero) labels of close points grow into each other; each keeps the server's spot unless that now hits a placed label (with a gap), a dot or a leader, else takes the least-colliding spot around its point. Leaders follow the new spot.
- `app.js:announceStatus` — `#announce-status` (role=status) carries secondary messages (shorter-proof search, history search/filter counts, "explanation ready") so they never cut the verdict announcement in `#announce`. `#ai-text` is not a live region. Both regions are cleared on a language switch.
- `app.js:refineShorter` — focus inside `#refine` goes to `#verdict-head` when the line is hidden; when a shorter proof is swapped in, `focusMark`/`restoreFocus` put focus back on the same control or step index.
- `app.js` editor — a right-edge fade (`.code.can-scroll-x`) shows while a line runs past the editor's edge.
- `site.js:fitLabels` — the constant-screen-size label logic, shared by the Viewer and the landing hero; `Viewer.reset` pads the view box when labels are drawn larger than the figure was framed for (high zoom, small panels).
- `site.js:toast` — at most one plain toast (no action button, class `plain`) is shown: a new plain toast closes the older ones, while action toasts (Undo, Share / Save, Cancel) stay. On coarse pointers plain toasts are `pointer-events: none`, so a tap on the field under one reaches the field (a tap would otherwise fire iOS's emulated `mouseenter` and pause the timer for good). The timer pauses while the toast is hovered or focused; no `role=status` (the region is the live region). While a toast is up, `html.has-toast` sets `scroll-padding-bottom` (and `.hist-list`'s) to `--toast-h` + 16 px, pads `body` below 1200 px, and a focused control under the toast is scrolled clear (`unobscure`, on show and on `focusin`; WCAG 2.4.11).
- `app.js:EXAMPLES` — each example has a comment per language (`\n` splits it into several `#` lines; the first line is the title, so the default one is short enough for the desktop editor); the editor is re-seeded on a language switch only while it still holds an untouched example.
- `app.js:showError` — errors keep their i18n keys so a language switch repaints them; a compile error is re-requested in the new language.
- `app.js:deleteHistory` — focus moves to the next row (or the search box); Ctrl/⌘+Z undoes within the 6 s window. Undo records, before re-rendering, whether focus was in the rail, the toast or on `body`; if so the restored row gets focus, and "Restored …" goes to `announceStatus`.
- `app.js:fitViewportToFigure` — on phones the figure panel's height follows the figure's aspect ratio (clamped 0.6–1.25); the cap is CSS `max-height: 70svh` (60svh on tablets), the small viewport, so iOS toolbars collapsing mid-scroll never resize the figure; on desktop the sticky frame shrinks (`--fig-fit`, never below 320 px of figure) when a wide figure would leave empty bands. Re-run on resize. `landing.js:fitCase` does the same for the case figure.
- `app.js:validSolution` — a 2xx answer without an `input` and a known `status` is an "unreadable answer" error; no verdict is ever inferred from a malformed body.
- `app.js` Escape — menus, the drawer and full screen `preventDefault` the Escape they consume; the global handler cancels a solve only for an unconsumed Escape with no layer open.
- `app.js:placeMenu` — menus are laid out off-screen to the left first, then placed inside the viewport (8 px margin); laying them out at an overflowing position first widened the phone layout viewport.
- `app.js:openHistory` — the previous result is cleared before the fetch and the editor changes only on success; a 404 removes the row. Replacing a program that differs from `S.baseline` (the last solved, opened or example program), or stopping a running solve (cancelled quietly, no “Solving cancelled.” toast), offers Undo via `offerDraftBack`.
- `app.js` undo — Clear, history deletes and `offerDraftBack` set `S.lastUndo`; Ctrl/⌘+Z works from the field focus was moved to while it is still untouched. On coarse pointers (`coarse()`) the toasts drop the shortcut sentence (`*.touch` keys) and the button its `aria-keyshortcuts`.
- `app.js` Clear — hidden while solving and on Describe/Photo when AI translation is unavailable; it acts on the active tab only and does nothing (no toast) when that tab is empty (`clearable`).
- `app.js:api` — a JSON answer carrying `x-solution-sig` keeps its exact text and signature as the non-enumerable `data.signed`; a non-JSON body is never shown as the error sentence, only as `detail` (technical details). Every result carries `retryAfter`.
- `app.js:recheckSession` — after `sessionEnded`, any successful API call, a `focus` or a `visibilitychange` re-reads `/api/status` (at most every 1.5 s); a valid session again restores the header and reloads history.
- `app.js:solve` — before posting, `/api/status` says whether a solver slot is free; if not, the card reads “Waiting for a free solver” for the server's queue wait (`queue_wait_secs`), then switches to the normal search timer. A 503 with `Retry-After` shows a countdown and retries once by itself (`S.autoRetried`); `busy_self` copy is pluralised by the server's `limit`.
- `app.js:solve` — “Shortest proof” runs the refine search only when the first proof has more than one deduction step; a refined answer (`search: "shortest"`) shows its time as “shortest-proof search: N s”.
- `site.js:fact` — relation symbols get screen-reader words (`sr.*` keys); `factText` (copy) keeps the symbols.
- `site.js:Viewer.stepPoint` — P / Shift+P in the focused figure walk the points in name order, highlight the steps using each and announce them.
- `site.js:toggleFull` — the figure panel gets `has-full` (z-index above the sticky header) while full screen.
- `site.js:lockScroll` — full screen and the history drawer lock the page by fixing `body` at `top: -scrollY` (`html.no-scroll`; counted, so both can nest) and restore the exact offset; `overflow: hidden` alone does not stop touch scrolling on older iOS. The drawer returns focus with `preventScroll`, or a non-sticky header would jump the page to the top.
- `site.js:Viewer` touch — a tap is a pointerdown→pointerup under 250 ms that moved ≤ 10 px with no pointercancel (a scroll flick cancels); a double tap is two taps within 300 ms and 30 px, so tapping two different points or two scroll flicks never zooms. `dblclick` is ignored after a touch (WebKit may fire one after a double tap, which would undo the zoom). While zoomed a one-finger vertical drag pans the figure until it hits the edge, then scrolls the page by the remainder (`panBy` returns what it applied), so a zoomed inline figure is not a scroll trap.
- `app.js:paintPeek` — below 1024 px the figure sits above the proof, so while a step, fact or cite lights objects and less than half the figure is on screen, a fixed thumbnail (`#fig-peek`, a clone of the figure SVG with the highlight, `aria-hidden`) shows them; it sits in the screen half away from the focused step, and a tap toggles a larger size limited to the room beside that step. It swallows `pointerdown` so the step keeps focus.
- `app.css` iPhone — `--sai-t/r/b/l` are the only readers of `env(safe-area-inset-*)` (tests override them to simulate a notch); every gutter (header, shell, footer, drawer, full-screen figure, toasts, landing/auth pages) pads with `max(gutter, inset)`. On coarse pointers or ≤ 767 px every text field, the editor's textarea/highlight/gutter (kept in step) and the history search are 16 px, so iOS does not zoom on focus; user zoom is never disabled. `:hover` rules live inside `@media (hover: hover)` with matching `:active` styles (a `touchstart` listener enables `:active` on iOS); the grey tap highlight is off. Touch targets reach 48 px (Android's 48 dp; above Apple's 44 pt) by size or by an `::after` hit area (segments, cites, pan buttons, the restated-steps toggle); cites are spaced 12 px so their hit areas never overlap. Below 360 px the header controls stay at 44 px so the header fits. Landscape phones (≤ 500 px tall) get a non-sticky header. At ≤ 767 px or on coarse pointers the header is opaque (`--bg`, no backdrop blur), so the composer's Clear/Solve never shows through it. The Solve button's `Ctrl ↵` hint is hidden on coarse pointers. `--vh-dyn` is `100dvh` where supported. `tests/mobile_css.rs` pins these; `tests/webkit/iphone-layout.mjs` checks them in WebKit with iPhone presets.
- `app.js:firstModeChoice` — runs once `/api/status` is no longer `checking` (and not if the visitor already picked a tab or is typing in the composer): AI unavailable → `.geo`; else the last tab the visitor *picked* (`gs.mode`), else Describe. Only tab clicks/arrow keys write `gs.mode`; programmatic switches (examples, history, compile errors, boot) never do, so they can't overwrite the choice.
- `app.js:aiOffKey` — the pill says "AI not set up yet" (`ai.unset`) for `not_installed`/`not_logged_in` (the operator has not signed the CLI in), "AI translation off" only for `disabled`, "AI needs sign-in" for `sign_in`.
- `app.js:paintGates` — on phones the header AI pill gives way to `#ai-pill-m`; in addition, when translation is unavailable the Describe and Photo tabs carry a hollow dot (`.tab-ai-dot`) and the reason in screen-reader text, so the tab itself says it is off.
- `site.js:keyboardSpace` — while a text field is focused, `--kb` is the part of the layout viewport the on-screen keyboard covers (`visualViewport`), and toasts sit above it.
- `auth.js` — server errors carry a `code`; field codes (`user_taken`, `username_rule`, `pw_len`) mark the field instead of a banner and are repainted on a language switch. Field hints are not live regions.
- `landing.js` — stats and the showcase blurb come from `showcase.json` (`first_secs`, `budget_secs`); the step count excludes restated hypotheses; the folded preview ends after `FIRST_DEDUCTIONS` deductions. Regenerate `showcase.json` by POSTing its `input` to `/api/solve` twice (plain, for `first_secs`; then `best: true, budget_secs: 20`) and keeping the second answer's keys.
- `site.js:placeLabels` — goal lines (`line.f-goal`, weight 12) and construction lines (weight 8) count as collisions that send a label away from the server's spot; a leader crossing a placed label and a spot nearer another dot than its own each cost 14. `f-ext` (dashed extensions to right-angle feet) are obstacles too, and so are circles (8, goal 12) and marks (8, scaled about `data-a` like the drawn mark), except a mark drawn around the label's own point.
- `app.css` figure focus — dimmed labels keep opacity 1 and switch to `--fig-lbl-dim` / `--fig-aux-dim` (≥ 5.8:1 on `--fig-bg` in both themes); lines and dots still fade.
- `app.css` header — `.seg`, `.icon-btn` and `.btn-sm` in `.site-header` share `--hdr-ctl` (36 px; 48 px on coarse pointers, 44 px there below 360 px).
- `app.css` verdict actions — a wrapping flex row (buttons grow, never truncate); meta items may wrap. Toasts sit bottom-right from 1200 px so they never cover the verdict actions; `.toast :focus-visible` uses `--bg` for its ring.
- `app.js:sessionEnded` — a 401 for a signed-in user (solve, history list/delete/open, export, shorter-proof search; see `authLost`) refreshes `/api/status`, swaps the header to Sign in and puts the session-ended message in the rail; `recheckSession` undoes it.
- `app.js:refineShorter` — “none found” only for a 2xx answer that is not shorter; a 503/429 says the server was busy, other failures say the search could not run.
- `app.js:exportName` — downloads are named by title and verdict; the suffix is the UI language's `export.suffix.<status>` (`-proof`, `-counterexample`, `-numerical`, `-not-proved`, `-figure`; RO `-demonstratie`, …) passed through `slug`, so it stays ASCII.
- `app.js:setPhoto` / `normalizePhoto` — a chosen photo is decoded through an `<img>` (the browser applies EXIF orientation and, in Safari, decodes HEIC), stepped down by halves and drawn on white at ≤ 2048 px long edge, then `toBlob('image/jpeg', 0.85)`; if that is still over `status.max_image_bytes` it retries at 1600/0.8 and 1280/0.75, then refuses with `photo.err.too_large`. The upload is always a metadata-free JPEG (~0.3–1.5 MB). `#dz-busy` shows while it runs, `#photo-meta` shows the size sent; Solve pressed meanwhile waits for it. `accept="image/*"` keeps iOS's camera / library / files choice and its HEIC→JPEG transcoding.
- `app.js:translateError` — a translate failure with a server `error` is shown under its own title (`translate_timeout` → "The AI took too long", `heic`, 413 → photo/description too large) before the generic 502/503 "server is not answering" copy, which is left for proxies with no JSON. The translate stage timer uses `status.translate_timeout_secs`.
- `app.js:deliver` — exports on touch screens or in a home-screen web app go through the Web Share API when `navigator.canShare({files})` holds: SVG shares straight from the menu tap; PDF/PNG finish after a fetch, so a "{fmt} is ready · Share / Save" toast (120 s) supplies the fresh tap `share()` needs. Share data is files only (title/text alongside a file is reported to hide iOS's "Save Image"; unverified on a device). On Android (`app.js:android`, user agent) PDF/PNG/SVG are always downloaded first (Chrome's download bar opens them; Android's share sheet often has no "save") and the "{fmt} downloaded" toast offers Share when `canShare({files})` holds. Otherwise `<a download>` with the blob URL revoked after 120 s. `copyText` falls back to `execCommand` and then offers Share.
- `app.js:histStatus` — `proved-drawn` (stored `as_drawn`) shows “Proved (as drawn)” under the Proved filter.
- `app.js:verdictModel` — a proof with no steps says it follows at once and offers no Copy proof.
- `site.js:fitLabels` — labels are at least 15 px on screen (`labelPx`); marks with `data-a` are scaled about their anchor by the label scale (1–2.2) so right angles and ticks stay visible in small panels.
- `site.js:Viewer` — while zoomed, a pan pad (four `.pan-btn` at the viewport edges, `fig.pan.*` labels) pans by 30 % of the view without dragging (WCAG 2.5.7); it is `hidden` at fit, and focus inside it moves to the viewport when it hides. The figure SVG is the viewport's direct `svg` child (`:scope > svg`), not the icons' SVGs.
- `app.css` layout — below 1024 px the app is one column (composer, status, figure, proof) and the figure panel takes the full width; `fitViewportToFigure` sizes it (≤ 60 % of the screen on tablets, 70 % on phones). 1024–1199 px (iPad landscape, iPad Pro 12.9 portrait) splits 1.1 : 1 so the figure keeps ~450 px; from 1800 px `--maxw` is 1760 px, the text column stops at 780 px (760 beside the rail) and the figure takes the rest (frame up to 1080 px tall), so a 1440p/4K/ultrawide screen gets a ~900 px figure instead of a 634 px one. Prose (`.verdict-text`, `.ai-text`, error text) stops at 75ch.
- `site.js:Viewer` wheel — Ctrl/⌘ + wheel and trackpad pinches (Chromium/Firefox send them as ctrl-wheel; Safari as `gesture*` events, handled only when no touch pointers are down so iOS pinches are not zoomed twice) always zoom the figure. A plain wheel zooms only when the figure is `pinned()` (a sticky/fixed ancestor: the desktop side column, full screen); over an in-page figure (one-column layouts, browser zoom ≥ 200 %, iPad with a trackpad) it pans a zoomed figure until the edge and otherwise scrolls the page, and scrolling down over a figure at fit always scrolls the page. Line/page `deltaMode` is scaled to pixels (read after `deltaY`, so Firefox keeps pixel deltas). `app.js:paintFigHint` says "Ctrl + scroll or pinch to zoom" (`fig.hint.wheel`, ⌘ on Apple) for an in-page figure, re-checked by a `ResizeObserver` on the viewport.
- `app.css` print — `@media print` forces the light tokens whatever the theme (dark labels and halos on paper were unreadable), hides the header, composer (once there is a result), tools, actions, hints, toasts, Details and footer, and prints verdict → figure (112 mm, never split) → statement → proof in one column; the highlighted step stays highlighted. Verdict tone, chips and figure use `print-color-adjust: exact`. The touch-target block is `screen and (pointer: coarse)`: printed from a phone or iPad, cites kept their 36 px chips and 12 px gaps on paper.
- `app.js:wirePhoto` — an image pasted (Ctrl/⌘+V, unless pasting text into a field) or dropped anywhere on the page switches to Photo and is prepared like a chosen file (`takeImage`; ignored while AI is unavailable or a solve runs). The document-level `dragover`/`drop` stop the browser from navigating to an image dropped beside the drop zone. Fine pointers read "Drop or paste a photo here" (`photo.drop.paste`).
- `app.css` `prefers-contrast: more` — `--text-3` → `--text-2`, borders → `--border-strong`, 3 px focus rings, delete buttons always visible, dimmed figure parts at 0.4. Forced colours draw the AI status dots with `CanvasText`/`Canvas` (their backgrounds and box-shadows are otherwise removed).
- `app.js:exportAs` — the menu click closes with focus back on Export. While a PDF/PNG export runs (`S.exporting` = its format, `S.exportCtl` its AbortController), the PDF and PNG items are `aria-disabled` (`paintExportItems`) and picking one toasts `export.busy`; Export itself and SVG stay usable. A 410 retries with the answer's signed copy (`{signed, sig}`, rendered as shown, no solve), then the stored history copy (`GET /api/history/{id}`), and only then exports by `{input, title}` — a re-run shown as a counting toast with Cancel. A 401 toasts `export.auth`; other failures go through `httpError`, so a proxy's HTML page never reaches the toast.
- `app.css` `.hist-list:empty` — does not grow, so the drawer's empty-history message sits under the filters. History rows keep badge and time on one line (relative time in the `short` style, ellipsized if still too long).
- `app.js:renderHistory(keepFocus)` — when the focused row disappears (stale 404, delete flush, reload) focus goes to the same row, the next one, the rail's Sign in link, or the search box; `sessionEnded` empties the rail synchronously and keeps focus there; a 401 on open focuses the error heading.
- `app.js:solve` — a solve that aborts a running shorter-proof search retries up to 4 × 350 ms on `busy_self`, since the server frees the aborted request's slot only once it notices the disconnect.
- `app.js:startTimer` — past its maximum the solving card reads “Finishing up · time limit N s” with a full bar instead of counting over the limit (queue wait and the worker's grace are not part of the deadline).
- `landing.js` — `#more` carries `aria-expanded`; expanding focuses the first newly shown step, collapsing keeps the button where it was on screen.
- `app.css` forced colors — `.editor:focus-within`, `.input:focus`, `.textarea:focus` get a `Highlight` outline (their normal ring is a box-shadow, which forced colors removes).
- `i18n.js` RO — hyphenated clitics (`fotografiaz-o`, `s-a`) carry a word joiner (U+2060) after the hyphen so lines never break there.
- `app.js:auxText` — mirrors `render.rs:aux_text`; `same` adds "(the same point as …)", and a second meet whose first object is a circle or a worded line uses `aux.intersect2_shape`.
- `app.js:paintGates` — while translation is unavailable, the empty state's body is `empty.body.geo` (no "describe a problem").
- `app.js:paintDocTitle` — `document.title` follows the visible state: “Title — Verdict · GeoSolver”, the error title, or the solving stage; plain “GeoSolver” when empty. Repainted from `show`, `paintStage` and on a language switch.
- `app.js:renderProof` — `#proof-steps-panel` is `role=tabpanel` only while the proof tabs are shown (a human proof or AI explanations available). With `view.human` the tabs are Proof (`#ptab-human`, selected first) | Full derivation (`#ptab-steps`, relabelled) | AI explanation; without one everything is as before ("Verified steps"). Arrow keys/Home/End move between the visible tabs; a language switch keeps the selected tab (`currentProofTab`).
- `site.js:hpDoc` — builds the human proof once as HTML parts from the engine's JSON model (`src/human_view.rs` CODEMAP note; the wording rules are `src/human_view.rs:doc`'s, in the same order, and `desktop-e2e.mjs:humanParity` compares the two texts on every fixture); `math` keeps `∠`/`∡`/`△` (and `sin∠`) with their point names (`.m-nb`); `renderHuman` lays it out, `humanText` (`opts.lang`, `opts.auxText`) gives plain text for Copy proof and, in English, for the AI tab. Blocks are an `ol` with the `renderSteps` roving tabindex (↑ ↓ Home End; `#hp-kbd` hint); hovering/focusing a block lights its points, statement and `objects`; hovering/focusing a chain row or inline link (`[data-l]`) lights only that link's reasons. Inner controls (chips, claim links, rows, toggles) are tab stops only in the active block. A chip calls `hooks.jump` (`app.js:jumpToStep`: Full derivation tab + `renderSteps().jump(n)`); a claim link flashes the claim. Display chains are tables (`role=list`, rows `role=listitem`); below 600 px they stack and their reasons fold behind "Show reasons"; pooled sentences with a `combination` get "Show the computation". Short relations are `.hp-nb` (no break inside); `renderHuman` also wraps a claim/step link with its trailing punctuation in `.hp-nb`, because on coarse pointers those links are `inline-block` (48 px targets) and would otherwise let ", the" start a line.
- `app.js:refineShorter` — the shortest-proof search's answer replaces the shown proof when it has fewer steps or, with a human proof, a lower `metrics.human_cost` (toast `shorter.readable`).
- `app.js:proofText` / `loadAi` — with a human proof Copy proof gives its text plus "Full derivation: N steps"; `/api/humanize` gets `human` (English) besides the raw steps.
- `app.js` Export menu — "Include full derivation" (`menuitemcheckbox`, only with a human proof; `S.derivation`, remembered in `gs.derivation`) adds `derivation: true` to `/api/export`.
- `i18n.js:tl` / `hasIn` — a lookup in a given language (`hasIn` does not fall back to English, so a missing Romanian `.np` key falls back to the Romanian base key, never to English).
- `app.css` short drawer — at ≤ 1199 × 480 px the whole rail scrolls and `#hist-list` has no inner scroller, so rows and their focus rings are never clipped. At ≤ 380 px the problem tabs drop their icons and the figure panel's "Figure" heading is visually hidden (still its accessible name) so the five tool buttons fit.
- `site.js:backLayer` / `dropLayer` — the history drawer and the full-screen figure push a history entry (`{gsLayer}`) when they open, *before* the scroll lock, so Android's Back button (and browser Back) closes them instead of leaving the app; closing them any other way pops that entry with `history.back()` (the resulting `popstate` is skipped), so Back afterwards leaves the page as usual and the scroll position is the one from before opening.
- `app.css` narrow screens (Galaxy Fold cover 280 px; Android page zoom from the system font size makes a 360 px phone 288/240/180 CSS px wide) — header, header tools, composer title, problem tabs, Search choice, Clear/Solve, figure tools, proof tabs and example chips wrap instead of widening the page; card grids use `minmax(0, 1fr)` columns. ≤ 440 px: no "GeoSolver" text beside a visible Sign in (`.site-header.has-signin`); ≤ 339 px: Sign in is an icon (`.signin-btn`, label kept for screen readers); ≤ 299 px: 8 px gutters, 12 px card padding, no wordmark beside the history button (`.site-header.has-rail-toggle`); ≤ 259 px: the header (possibly two rows) is not sticky and verdict/error icons go. `body` has `overflow-wrap: break-word`, so a word longer than its box (Romanian at a 200 % font size) breaks instead of widening the page. `@container verdict (max-width: 260px)` drops the action indent and lets button labels wrap (no-container-query copy at ≤ 325 px of viewport). `has-signin` / `has-rail-toggle` are classes set by `app.js:paintAccount` (static `has-signin` on the landing header), not `:has()`, because Samsung Internet 17–19 and Firefox < 121 — Android browsers inside the baseline — have no `:has()`. Full screen at ≤ 319 px tall hides the legend row. `tests/webkit/android-layout.mjs` checks all of it.
- `app.js` editor — the textarea height uses its computed `line-height` (25.6 px at the 16 px touch size), not a 14 px constant, so 6–17 lines never scroll inside the box.

## Browser support
- Baseline: Safari / iOS 15.4+, Chrome / Edge / Opera 100+ (incl. Android WebView), Samsung Internet 17+, Firefox 100+ / ESR 115. `tests/compat.rs` (part of `cargo test`) fails on CSS or JS newer than that without a fallback; `tests/compat-inventory.mjs` lists every feature against MDN's compat data.
- The page scripts are ES5 syntax (they parse as ES5); keep them so, the inline guard included.
- Old-browser guard — the second inline `<head>` script of `index.html`, `landing.html` and `auth.html` checks what the app cannot run without (`fetch`, `Promise`, `Map`/`Set`/`WeakMap`, `AbortController`, `ResizeObserver`, `IntersectionObserver`, `PointerEvent`, `Intl.PluralRules`/`RelativeTimeFormat`, `Element.closest`, custom properties, grid, `aspect-ratio`; that is Safari 15.0 / Chrome 88 / Firefox 89). Missing any → `html.gs-old`: only `#gs-old` (“update your browser”, EN or RO by the language the first snippet picked) is shown. `gate.html` has no script: its `#gs-old` is shown by CSS unless `@supports (aspect-ratio: 1 / 1)`, and the form still works.
- `GS.booted` — set at the end of `app.js`, `landing.js` and `auth.js`; if it is not set by `load` (a script failed to download or threw during start-up) `html.gs-fail` shows `#gs-fail`, a banner with a plain `<a href="">` Reload above the page.
- `<noscript>` — every scripted page shows an EN + RO “needs JavaScript” note; the app and sign-in pages hide everything else (`<noscript><style>` in `<head>`), the landing page keeps its text. The notes are styled by a page-local `<style>` with literal colours, so they render even where `app.css` custom properties do not.
- Between the guard floor and the baseline these degrade on purpose: `:focus-visible` (Safari < 15.4 falls back to the UA focus ring), `text-wrap`, `overscroll-behavior`, `scrollbar-width`, `subgrid` (landing feature cards keep their own rows), `backdrop-filter` (the header is opaque `--bg` first), `forced-color-adjust`, the `-webkit-` only properties. From the device branches: `@media print`'s `@page` margins (Safari < 18.2 uses its own), `prefers-contrast` (Firefox < 101: no high-contrast tweaks), `print-color-adjust` (Chrome < 136 reads the `-webkit-print-color-adjust` declared before it) and `navigator.userAgentData` in `app.js:android` (presence-checked, after the user-agent test).
- `app.css` translucent colours — `--accent-a28`, `--focus-a25`, `--hl-a14`, … are the `rgba()` equal of the old `color-mix(in srgb, X p%, transparent)` and are defined in all three theme blocks and in the `@media print` light tokens; keep them in step with the base colour. `color-mix()` remains only after a plain fallback declaration (header, toast button border, pan buttons, spinner).
- `app.css` `:has()` — only ever alone in its rule: in a selector list, a browser without `:has()` drops the whole rule. The photo dropzone ring has an `@supports not selector(:has(a))` twin driven by `.dropzone.is-focused` (`app.js` focus/blur on `#photo-input`).
- `app.css` `@container verdict` — each `@container` rule has an `@supports not (container-type: inline-size)` copy under a viewport media query: 520 px → `max-width: 585px`, 260 px → `max-width: 325px`. The query measures the verdict's *content* box, which is the viewport minus 65 px below 768 px (measured in Chromium: 523 px at 588, 505 px at 570); the first copy used 552 px, which left 553–585 px unwrapped without container queries.
- `site.js:modal` without native `inert` (Chrome < 102, Firefox < 112, Safari < 15.5) — the inerted siblings also get `aria-hidden="true"` (old value kept in `data-gs-inert`) and a `focusin` listener sends focus that lands in them back into the dialog.
- `i18n.js:current` — the language is read once and then kept in memory (`chosen`); `set` updates it. With storage and cookies both refused the EN/RO switch used to fall back to the browser language on every lookup, and re-reading storage per string cost ~70 ms at 6× CPU for a long proof. `fmtNum` caches its `Intl.NumberFormat` per locale and digits.
- `app.js:solve` watchdog — each stage aborts its request `STALL_GRACE` (35 s) after its own limit (`S.deadline`, `translate_timeout_secs`) and shows “No answer from the server” with Retry, so a connection that dies silently never leaves a spinner.
- `app.js:networkError` — with `navigator.onLine === false` the error is “You're offline” (`offline: true`); the `online` event re-runs that solve and retries a failed `/api/status`. `loadStatus` backs off 2, 4, 8, … ≤ 30 s, six tries.
- `app.js:api` — the `Date` header of every answer sets `S.skew`; `relTime` uses the server's clock, so a phone whose clock is hours off still reads “now” for a fresh history row.
- `app.js` history deletes — where `Request.keepalive` is missing (Firefox < 133) pending deletes are also flushed when the page is hidden; Undo does nothing for a delete that was already sent.
- `app.js:wireVerdictActions` — the outside-click closer of the Export menu is one document listener installed once; it was added per verdict and kept every old verdict alive (+40 DOM nodes, +6 listeners per solve).
- `auth.js` — after a successful sign-in or sign-up, `/api/auth/me` must answer 200 before going to `/app`; otherwise the browser refused the session cookie and `auth.err.cookies` says so.
- `index.html` preloads only Inter; STIX italic (figure labels) is fetched when a figure first needs it. Measured on Slow 3G it cost ~0.6 s of LCP on the empty app.
