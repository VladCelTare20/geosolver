# ag-studio/src — the `agstudio` binary: CLI, web app, MCP server

Up: [../../CODEMAP.md](../../CODEMAP.md) · Web assets: [../assets/](../assets/CODEMAP.md)

## Files
- `main.rs` — subcommands `render`/`best`/`translate`/`serve`/`mcp`, plus the hidden `__solve-worker`; unknown flags exit 2.
- `engine.rs` — solve wrapper: routes DDAR vs metric goals, reconciles a proof against the numeric check, `solve_within` deadline. `Status` (`proved` / `holds-numerically` / `refuted` / `not-proved`) is set only in `reconcile`; `proof` is `Some` only when proved, numeric reports go in `numeric_evidence`. `Solution.figure` (never serialized) carries the problem the figure is drawn from, search-augmented when aux points were added.
- `worker.rs` — killable solves: `run` (parent) spawns `agstudio __solve-worker`, `worker_main` (child) solves one JSON request and prints one JSON reply line (with the `present` view and/or a rendered report when asked); `arm_watchdog` is the hard-exit timer shared with the CLI.
- `present.rs` — presentation only, never changes a verdict: readable names for anonymous points, typed facts (`Fact {kind, args, points}`), the proof as numbered cited steps, classified notes, numeric counterexamples, compile-error diagnosis, and `solution_json` (engine fields + `view` + `title`).
- `figure.rs` — the web/export figure SVG: framed to the points, labels and every circle up to 1.5× the construction's size (only larger circles are clipped), every element classed and tagged with `data-p` (its points); light colours as attributes so exports render without CSS. Labels of points with a neighbour closer than 1.6 label heights may sit farther out and get a thin leader line (`f-lead`, re-laid out by `site.js:fitLabels`).
- `spread.rs` — display only: `respread` redraws a figure that is crowded (closest two distinct points < 3.5 % of its extent), badly shaped (a `X Y Z = triangle` of the program with an angle under ~30° or over ~81°, or two angles within ~6°) or badly framed (a circle stretching the frame, or the triangle small in it) from the best instance of the same program (`ddar::geo::build_instances`, 12/48/160 seeds within 1.5 s; score = product of the shape, spread and framing terms). Accepted only if every hypothesis holds numerically and the goal holds (`Goal::Holds`) or, for a refuted claim, still fails (`Goal::Fails`).
- `render.rs` — SVG→PNG/PDF and the report built from `solution_json` (verdict tone per status, localized, verified steps only): A4 pages for PDF (`report_pdf_from_json`, assembled with `pdf-writer` from one svg2pdf chunk per page), one tall page for PNG.
- `translate.rs` — photo/text → `.geo` via `claude -p`, locked down (no tools or Read-one-file, no settings/MCP/hooks, empty cwd, no API-key env).
- `web.rs` — axum routes and handlers; static assets table; recent-solution cache for export/reopen.
- `security.rs` — env config (the env table is the source for `deploy/DEPLOY.md`), the shared-password middleware (`auth`: gate cookie, then Basic), `PUBLIC_PATHS`, guest mode, rate limits, Host/Origin guards, CSP, `hmac_sha256`.
- `gate.rs` — the `/gate` password page (`assets/gate.html`, rendered server-side, no JS), its signed cookie (`mint`/`verify`), `sanitize_next`, `POST /gate` and `/gate/forget`.
- `pwa.rs` — Home Screen support: `/manifest.webmanifest`, icons and launch images rendered from the brand mark with resvg on first request (RGB PNGs, cached for the process), the splash `<link>`s injected at `<!--pwa-splash-->`, `/robots.txt`.
- `auth.rs` — argon2 (gated, dummy-hash for unknown users), session ids, cookies.
- `db.rs` — SQLite: users, sessions (hashed), history (verdict `status`, display `goal`, full `solution` JSON; older rows have `NULL`s). Solving the same input again with the same title, method and verdict replaces the old row rather than stacking a duplicate; `replace_history` swaps a row's result in place (same input only); listings carry the stored note key (`json_extract`); files created 0600.
- `mcp.rs` — stdio JSON-RPC MCP server; exports confined to `AGSTUDIO_EXPORT_DIR`.
- `i18n.rs` — server-side EN/RO strings: errors (full sentences with an action), compile diagnoses, report text; `tf` fills `{placeholders}`, `tp` picks `.one/.few/.other` (Romanian CLDR rules); `prose_ro`/`theorem_ro` translate the Euclidean prover's closed set of English sentence templates and theorem names.

## Notes
- `worker.rs` — why processes: a DDAR closure is not interruptible and `solve_within` checks its deadline only between closures, so an in-process timeout abandoned a thread that kept the CPU (and, in `web.rs`, its semaphore permit). Every web/MCP solve and export now runs in a worker; only the CLI solves in-process.
- `worker.rs:run` — child in its own process group, `kill_on_drop`, nice +10 (so `/healthz` stays fast under load), `RLIMIT_DATA` = `AGSTUDIO_WORKER_MEM_MB` (default 2048), `RLIMIT_CPU` = threads × hard limit (backstop only), no core dumps. Hard limit = the solve's deadline/budget + `GRACE` (5 s); past it the group is SIGKILLed and the caller gets `Outcome::TimedOut`, reported as `not-proved` with a "time limit" note (web export: 504; MCP export: error).
- `worker.rs:Slot` — the caller's permit lives in the same guard as the child and is dropped only after the child is reaped: on success, on timeout, and when the future is dropped (HTTP client gone, `TimeoutLayer`, MCP `notifications/cancelled`), where a spawned task reaps the SIGKILLed child and then frees the slot.
- `worker.rs:run` — the cap is `RLIMIT_DATA`, not `RLIMIT_AS`: glibc reserves 64 MB of address space per malloc arena (8 × cores) plus a stack per rayon thread, so under a 2 GB `RLIMIT_AS` an IMO solve aborted at ≥ 31 threads and at 128 rayon could not start its pool (swallowed by the aux search as "no proof"). `RLIMIT_DATA` counts only committed writable memory; 64-thread IMO P2 is a test.
- `worker.rs:worker_main` — before solving: `PR_SET_DUMPABLE` 0 (`RLIMIT_CORE` 0 alone still pipes every crash to systemd-coredump), a `parent-watch` thread that exits 125 within 100 ms once `getppid()` is no longer the server (pid in `AGSTUDIO_WORKER_PARENT`; workers are in their own process group, so Ctrl-C/SIGTERM/SIGKILL of the server never reached them; `PR_SET_PDEATHSIG` is avoided because it fires when the forking tokio *thread* exits), its own watchdog at hard limit + `GRACE`, and the rayon pool built up front (exit 3 if it cannot start, so a thread failure is `Outcome::Failed`, never a not-proved answer). Exits 101 on a panic, 124 from the watchdog. Dying messages go through `last_words` (≤ 200 ms), since stderr may be an undrained pipe.
- `worker.rs:worker_command` — production execs `/proc/self/exe` (survives the binary being replaced on disk). Under `cargo test` it re-runs the test harness filtered to `tests::worker_process_entry`, which is why the reply is read as the *last* stdout line; the test-only inputs (`__agstudio_test_hang__` etc.) exist only in `cfg(test)` builds.
- `web.rs:serve_on` — binds and answers before the `claude` probe (up to 15 s per candidate) finishes; it reports in the background. `accept_loop` replaces `axum::serve` only to get a header-read timeout (`Config::header_timeout`, 30 s; axum sets none). HTTP/1 `half_close` stays off on purpose: hyper cannot tell a half-closed client from one that left, and read-EOF is what kills a disconnected client's worker.
- `web.rs:upright_jpeg` — every uploaded photo is sniffed by magic bytes (never by file name), decoded with the `image` crate (PNG/JPEG/GIF/WebP; HEIF/AVIF → 415 `code: "heic"`), turned upright by its EXIF orientation, scaled to ≤ 2048 px long edge, flattened on white and re-encoded as JPEG q85 — so EXIF/GPS never reach the temp file, the CLI or the model, whatever the client sent. Decoding runs on the blocking pool after the heavy permit; base64/size/HEIF checks run before it. `upload_image_limit` is the real photo ceiling (`min(8 MiB, (body − 4 KB) · 3/4)`, 6.0 MiB at the default 8192 KB body) and `/api/status` reports it as `max_image_bytes`, with `translate_timeout_secs` (= `translate::CHILD_TIMEOUT`, 90 s) for the client's timer.
- `web.rs:translate_failed` — model failures are 502 with a `code` the client words by: `translate_timeout` (CLI killed at 90 s), `cannot_translate` (no program / "cannot translate"; photo wording when the input was an image), `translate_unavailable` (CLI signed out), `translate_failed` (anything else). The kind comes from `translate::Failure`, attached to the error chain by `translate.rs` (`translate::failure`). `ApiJson` answers an over-limit body with 413 `code: "body_too_large"`.
- `web.rs:heavy_permit` — waits up to `AGSTUDIO_QUEUE_WAIT_SECS` (5) for a slot, then 503 `code: "busy"` + `Retry-After: 10`. `/healthz` and pages never touch the semaphore. `/api/status` reports `solver_free` and `queue_wait_secs` so the client can say a solve is waiting in line.
- `security.rs:SOLVE_DEADLINE` — 60 s (`Config::solve_deadline`), so hard limit 65 s, inside the 120 s request timeout.
- `mcp.rs:serve_io` — tool calls run as tasks (at most `AGSTUDIO_MAX_CONCURRENT`, default 2) while the loop keeps reading; a cancelled request gets no response; an id already in flight is refused (-32600) so a cancel always reaches its call. A call waits for a slot at most its own limit (≥ `MIN_QUEUE_WAIT`, 5 s), then gets a "busy, retry" tool error. At EOF (MCP shutdown) calls still waiting for a slot are answered "not started"; running ones finish, then the last replies get `FINAL_FLUSH` (60 s) to be read.
- `mcp.rs:spawn_writer`, `note!` — stdout replies (~400 KB with the figure) and stderr diagnostics are written by their own threads: a blocking write on a runtime thread starved the timer that kills overrunning workers when the client was slow to read.
- `main.rs:arm_hard_limit` — `render`/`best`/`translate --solve` exit 124 with a message if the solve overruns `--timeout`/`--budget` + `GRACE`.
- `translate.rs:run_with_timeout` — after the child exits, its output is awaited only 2 s; a process it left holding the pipes gets its group killed, then the call fails rather than hanging.
- `security.rs:client_ip` — rightmost X-Forwarded-For, honoured only from a loopback/private peer with `AGSTUDIO_TRUST_PROXY=1`.
- `security.rs:translate_status_now` — `/api/status` never waits for the `claude` probe: it answers from the last result (or `translate_checking`) and refreshes in the background; `serve` warms it before binding.
- `web.rs:cache_put` — every solve answer gets a random `id`; `/api/export {id}` renders exactly that result (no re-solve) for 30 min. The cache is keyed by owner (`caller_key`): at most `SOLUTION_CACHE_PER_OWNER` (24) entries each, 256 in all, and when full the owner holding the most loses its oldest — so one caller's flood evicts only its own results. History rows store the full JSON (≤ 512 KB) and `GET /api/history/{id}` re-registers it.
- `web.rs:signed_json` — solve and history answers carry `x-solution-sig`, an HMAC-SHA256 of the exact body under a per-process random key. `/api/export {signed, sig}` renders that body as is when its cached copy has expired (no re-solve, so the document matches the screen); an edited body or another process's signature is 410 like an expired id. Results with `best` set carry `search: "shortest"`, and the report's meta line then labels the time as the shortest-proof search's.
- `web.rs:compile_err` — `{error, code: "compile", diagnosis: {key, line, col, len, token}, detail}`; `error` is the localized sentence, `detail` the engine's words.
- `present.rs:Names::build` — `_5` from `reflect(H, …)` becomes `H′`, a midpoint `M`/`N`, else `P₁, P₂…`; the same map renames figure, facts, steps and aux text, so engine names never reach the page (raw `proof`/`low_level` keep them).
- `present.rs:parse_euclid_proof` — the Euclidean provers' indented lines belong to the step above them: `↳ NNN. rule: …` closure facts are parsed like DDAR lines (`ddar_line`) and only the derived ones kept as `Step.subs` (a closure heading with none is dropped and citations renumbered); `· …` sine relations become prose sub-items. `[from N]` becomes `deps`; points a proof introduces (`Let N be …`) are added to the names (`Names::with_points`). Any line ending in `∎` is the conclusion, its echoed goal typeset with `pretty_metric` (as the PROVE card); `Adding the relations above` with a single relation reads `Hence`.
- `present.rs:euclid_rule` — the rule label of a Euclidean sentence: `construction` (`Let …`), `closure`, a named theorem (`known_theorem`: the earliest of `KNOWN_THEOREMS` it mentions, so the ratio lemma is not called the law of sines), `trig`, `rearrange`, `area`, `segments`, `other`, else `combine`. Never `algebra` (kept only as a label for stored older results). `smooth_euclid` drops the `X (derived…), so X.` echo and rewrites `; times k`.
- `present.rs:diagnose` — the metric lexer's `Debug` tokens (`Op('*')`, `Ident("x")`, `LParen`, …) are turned back into source text (`token_text`); `angle got 2 arguments` is an `arity` error located on the `prove` line (`metric_arity`).
- `present.rs:build` — when a program states an `assume` relation the engine can only hold as a raw predicate (an angle sum), GIVEN shows the user's `assume` line typeset instead of the engine tuple.
- `present.rs:ddar_line` — a theorem step whose statement contains `=` (the engine's spelled trig rows) becomes a `formula` fact, not a point list.
- `present.rs:drop_restatements` — the engine re-states hypotheses (`collinear: A I M [003]` after `assumption: coll A I M`); those steps are folded into the cited one and citations renumbered. The step count shown is the folded one; `proof_steps` stays the engine's.
- `present.rs:diagnose` — the engine's compile errors carry no position: by-name errors are found by token; parse errors by compiling growing prefixes until the same message appears (≤ 1.5 s).
- `worker.rs:execute` — `present::solution_json` needs `Solution.figure`, which is not serialized, so the view (`Request.present`) and every report (`Request.report`, rendered from that view in `Request.lang`) are built inside the worker; the server only caches the returned JSON. `web.rs:view_of` builds the view itself only for the time-limit verdict of a killed worker (no figure).
- `web.rs:api_export` — `{id}` renders a cached view in-process under the `render` semaphore (no solve; the JSON came from a worker); `{input}` is a fresh solve and runs in a worker like `/api/solve`.
- `translate.rs` — `--bare` is deliberately absent: it limits auth to `ANTHROPIC_API_KEY`, breaking subscription login.
- `engine.rs:deductive_flow` — the aux search is `ddar::aux_search::solve_max_until`, the corpus benchmark's pipeline (`bench.rs:prove_goal`: DDAR, then the full depth-1 sweep and coincidence-ranked rollouts until the deadline). The rollouts never stop by themselves, so a deadline-less solve gets `DEFAULT_SOLVE_TIMEOUT`. `AUX_MAX_RUNS`/`AUX_MAX_DEPTH` (`security.rs:apply_process_limits`) only bound the legacy fallback now.
- `engine.rs:best_deductive` — depth 1 is `depth1_solvers` (the same pool, swept once in parallel, every solver proof-extracted and compared); the depth-2 hunt from the shortest bases still uses the classical `candidates`; with no depth-≤1 proof the rest of the budget goes to `rollouts_until` (or `solve_max_until` when the sweep was cut short).
- `engine.rs:with_keepalive` (tests only) — every `run_until` thread holds a clone of the guard, so a test can see that a search abandoned at its deadline really exits. Servers do not need it: their solves are worker processes.
- `security.rs:claim_caller` — caps each caller (user id, or the browser's guest id) at half the solve slots, so one account cannot lock others out (503 `busy_self` with the `limit`). Exports of cached results use their own `render` semaphore, not solver slots.
- `web.rs:claim_solve_slots` — guests are keyed by the `gid` cookie (`__Host-gid` over HTTPS; set by `with_guest_id` on `/`, `/app` and `/api/status`), falling back to the address without one. All guests behind one address share `guest_ip_limit` (every slot but one); hitting that ceiling is the plain 503 `busy`, never `busy_self`, since other people hold those slots.
- `present.rs:bisector_helpers` — `bisector(…)` compiles to an anonymous point X with `eqangle V A V X V X V C`. When neither the proof nor an aux point cites X, GIVEN states the bisector through the program's own point on that line (`∠BAR = ∠RAC`, the placing collinearity dropped) and the figure draws no X (`without_helpers`: substituted, coordinates NaN). When the proof cites it, GIVEN defines it (`bisector` fact: “P₁ is a point on the bisector of ∠BAC”). A hidden X is also left out of `View.helpers`; GIVEN runs the `twins` collapsing over the helper-free problem (`given_src`), and a defined bisector helper is stated as the `bisector` fact before any twin rewrite.
- `security.rs:auth` — under `AGSTUDIO_GATE=form` (default with a password): `PUBLIC_PATHS` (GET/HEAD; POST only `/gate`, `/gate/forget`) pass; then a valid gate cookie (a page load with one older than 7 days gets a fresh one); then Basic (a page load that passes by Basic also gets the cookie). Otherwise a navigation (GET/HEAD with `Sec-Fetch-Mode: navigate`, or no `Sec-Fetch-Mode` and `Accept: text/html`) is 303 to `/gate?next=…`, `/api/*` is 401 `{code: "gate"}` (localized), anything else 401 text; `WWW-Authenticate` only when the request has no `Sec-Fetch-Mode` (a challenge on a browser `fetch()` pops Safari's credentials sheet). `GateVia` (cookie/Basic) is a request extension; `/api/status` reports `gate: "cookie"`.
- `gate.rs:verify` — cookie `v1.<iat>.<b64url HMAC(key, "agstudio-gate\0v1\0" iat "\0" cred_digest)>`; `cred_digest` = SHA-256(user digest or 32 zero bytes ‖ password digest), so a new password (or user) revokes every cookie; ≤ 128 bytes, exactly one cookie of that name, `iat` ≤ now + 300 s and ≤ `AGSTUDIO_GATE_DAYS` old. The key is `AGSTUDIO_GATE_KEY` or the `server_secrets.gate_key` row (`db.rs:server_secret`), never the per-process `signing_key`, so restarts keep devices signed in.
- `gate.rs:submit` — the wrong-password budget is the Basic one (`AppState::password_guesses_exhausted` / `count_wrong_password`), checked before the password is; 429 + `Retry-After: 60`. An empty password is 400 and not counted. The visible username field appears only for a `user:pass` spec; otherwise a read-only `username=GeoSolver` gives iCloud Keychain a stable account name.
- `gate.rs:sanitize_next` — `next` must start with one `/` (not `//`, `/\`), contain no backslash or control character, be ≤ 2 KB and not start with `/gate`; else `/`. `location_of` escapes non-ASCII for the `Location` header.
- `security.rs:security_headers` — `Referrer-Policy: same-origin`, not `no-referrer`: under `no-referrer` WebKit (and Chromium) send `Origin: null` on a form POST, which `same_origin` refuses, so the gate form and "Forget this device" were 403 in Safari (seen in Playwright WebKit). `same-origin` still sends nothing to other sites.
- `i18n.rs:lang_from_headers` — the `lang` cookie, else the highest-q `ro`/`en` in `Accept-Language`, else English; `GET /gate?lang=` sets the cookie server-side (not `HttpOnly`, so `i18n.js` reads it; no 7-day ITP cap as for script-written cookies).
- `web.rs:api_translate` — takes `Caller`: guests may translate when `Config::guest_ai` (default = guest mode); else 401 `code: "sign_in"`. Guests also count against `AGSTUDIO_GUEST_AI_PER_DAY` per address (429 `code: "daily"`). `api_status` reports `sign_in` only when guests are not allowed AI.
- `pwa.rs:icon` — the opaque icons are `#f7f7f5` with the mark at 68 % (stroke ≈ 10 px at 180 px); the maskable one is full-bleed accent with a white mark of radius 150 (inside the 204 px safe circle); `favicon.ico` is a 32 px PNG in an ICO container. Launch images exist only for `SPLASH_SCREENS` (portrait, light and dark).
- `web.rs:page` — HTML pages are `Cache-Control: no-store`, so Back after logout re-asks the server (302 to `/auth`) instead of showing the previous user's page from cache.
- `web.rs:api_solve` — a metric-prover parse or name error (`input_error_note`: bad number, trailing tokens, unexpected token, non-numeric exponent, unknown name, …) is answered as a compile error, never as a verdict and never recorded; `degenerate_goal` refuses goals that repeat a point (`cyclic(A, B, C, A)`, `perp(A, A, …)`, `cong(A, B, B, A)`) as `degenerate_goal` before solving. Recorded solves return `history_id`; `PUT /api/history/{id} {id: <cached solution id>}` replaces that row (the client does this when "Shortest proof" swaps in a shorter proof).
- `present.rs:disp` — names written with a capital keep their case (`Ma` stays `Ma`, the client sets the lower-case suffix as a subscript); low-level lower-case names are upper-cased as before.
- `present.rs:transfer_fact` — the engine's `|AN| ↔ |CN|` (a fixed length ratio moved between its tables) is shown as `AN = CN` or `AC : AN = 2`; the constant is read from the figure and accepted only as a small-denominator rational (p/q, q ≤ 12) matching to 1e-6.
- `present.rs:three_on_a_circle` — a three-point "concyclic" step names the circle's centre among the figure's points (`F, B, A lie on a circle centered at Mc`).
- `present.rs:as_drawn` — the metric prover reads betweenness off the sampled figure; the step says "(as drawn)" instead of letting it pass as a hypothesis, and `View.as_drawn` makes the app and the report say "Proved as drawn" (the history chip: "Proved (as drawn)").
- `present.rs:theorem_fact` — DDAR's named theorems (angle bisector and its converse, radical axis, Monge–d'Alembert, homothety, intercept theorem) are shown as the fact they derive, not a bare point list; `i18n.rs:theorem_ro` names them in Romanian.
- `present.rs:diagnose` — metric-goal errors are located on the `prove` line; an unknown lower-case name that is a whole definition right-hand side is `unknown_shape` (only `triangle`/`segment` define several points), otherwise `unknown_construction`.
- `render.rs:report_pages_fit` — restated hypotheses are one line (`Steps 1–8, 10 restate …`); sub-items are bullets under their step; the ∎ sits right-aligned in the number column. A figure at most ~62 % of the text width gets GIVEN/PROVE beside it, and a report that would spill onto a second page shrinks its figure down to `FIG_MIN_H` — so a proof of about ten steps fits one A4 page.
- `render.rs:Typeset` — `sin∠BAC`, `cos∠ABC` and `△ABC` italicise the point run after the symbol; proof-introduced points (from the steps' `points`) count as names.
- `figure.rs` label placer — label boxes keep `LABEL_GAP` apart, and a candidate is penalised when its leader crosses a placed label or its box crosses a placed leader. Every crowded label gets an `f-lead` (hidden with `display="none"` while too short), so the client can show it after re-placing the label.
- `web.rs:compile_detail` — the "technical details" text is dropped when it is only `no attempt`, and an unknown relation shows the relation compiler's words, not the metric fallback's.
- `web.rs:advertise_limit` — a time-limit verdict states the configured limit (`job.limit()`), not the engine's measured 58 s.
- `web.rs:clean_title` — a title over `MAX_TITLE_CHARS` is cut at a word and ends with `…`.
- `render.rs:verdict_copy` / `method_text` — the report's verdict sentence and meta line use the same wording as `app.js:verdictModel` / `methodText` (keep `report.*` in `i18n.rs` and `v.*` in `i18n.js` in step). Pagination keeps a heading with its first lines and never leaves one list item alone; a report that spills a little onto page 2 gets a smaller figure instead.
- `present.rs:Fact.ro` / `Step.rule_name_ro` — Romanian text for Euclidean prose steps and cited theorems; client and report pick them by language.
- `render.rs:Typeset` — point names in report lines are set in "GeoSolver Math" italic. A font change inside one `<text>` makes resvg reshape the whole run with a fallback font, so the bundled export fonts (`assets/fonts/LICENSES.md`) carry the math symbols themselves rather than mixing families.
- `present.rs:angle_sum_text` — the engine's `angeq L1 … Lk c1 … ck c` (Σ cᵢ·dir(Lᵢ) + c = 0) is typeset by pairing lines with opposite coefficients through a common point into one angle, read from the negative-coefficient line to the positive one. In `build`, a given (or concluding) step whose fact is such an engine-only relation shows the user's `assume` line (or the goal as written) instead; no step text ever starts with a raw predicate name (test `engine_predicates_never_reach_the_proof_text`).
- `present.rs:pretty_metric` — ends with `trig_powers` (`cos∠ABC²` → `cos²∠ABC`) and `angle_degrees` (a bare number that is an additive term of an angles-only relation gets `°`; coefficients such as `2 · ∠ACB` do not).
- `present.rs:claim_multiplier` / `scaled_relation` — `Multiply both sides by k, which is not 0` becomes `Multiply both sides of the claim by k (k ≠ 0): it becomes …` with the goal multiplied out; `…, so X = Y; times k` becomes `…, so X = Y, hence k·X = k·Y`. `is_pythagorean_identity` labels `sin²∠X + cos²∠X = 1` with its theorem name.
- `present.rs:parse_euclid_proof` — closure facts: a mirror similarity △XYZ ∼ △YXZ is shown as `ZX = ZY` (`mirror_similarity`), equal-length facts that restate a hypothesis of the same closure are dropped (`cong_key`), and every claim a later step marks `(derived from the hypotheses)` while citing the closure is listed under it (`cited_closure_facts`, rule `derived`), so each `← from N` points at a visible fact. `circle_through` writes `the circle (O) through A, B, C`; `unbar` drops `|BC|` bars.
- `present.rs:proof_points` — points a Euclidean proof introduces (`Let N be the second meet of line IA with the circle (O) through ABC`, intersection, foot, midpoint, reflection, circumcentre, antipode) get coordinates from the figure and are added to it as aux points (`with_introduced`, dashed with their defining line/circle) and to `View.aux`; the angle-defined `point on AB with ∠… = ∠…` is not drawn.
- `present.rs:diagnose` — `expected a point` on a `X = circle(…)`-style definition is `not_a_point` on that line; `sin(A)` (a trig function of a bare name) is `trig_angle` on the argument; `expects at least N arguments` is `arity_min` (“takes at least 3 points”). `readable_engine_message` turns `Some(RParen)`/`None`/`LParen` in the engine's words into source text for the technical details.
- `figure.rs` right angles — a mark is drawn only where both legs lie on drawn geometry; when the foot is off a drawn side (obtuse triangles) the side is extended to it with a thin dashed `f-ext` segment (at most half the frame), else the mark is omitted. Area goals draw their triangles' sides as goal segments.
- `figure.rs:place_labels` — one placer for the server and `relabel`: goal lines weigh 12 (as a label collision, 14), a leader crossing a placed label 14, a spot nearer another point's dot than its own 14, construction lines, circles and marks 8; a mark drawn around the label's own point (`own_mark`: its `data-a` anchor, or every point of an unanchored goal mark within 26 px) only 2.2. `relabel` reads `data-a` back so the report judges marks the same way.
- `figure.rs:relabel` / `render.rs:fit_figure` — the report re-lays the figure's labels, dots and leaders at the scale it is printed at, so labels are `LABEL_PT` (10.5 pt) on every page whatever the figure's extent (test `report_labels_are_a_fixed_size_on_the_page`).
- `render.rs:wrap` — a relation or operator (`=`, `+`, `−`, `·`, `:`, `⁄`, …) and its operands are one unbreakable run (`math_atoms`); a run longer than a line breaks at its spaces.
- `render.rs` pagination — content may run to 8 pt above the footer rule; a tail of ≤ 3 blocks that fits above the rule stays on the page, and a last page that would hold fewer than 3 blocks gets its break moved earlier (`breaks_for`). The verdict bar is clipped to the card's rounded shape; the restated-hypotheses row is set at the 8.5 pt meta size.
- `web.rs:division_by_zero` — a goal dividing by a literal zero is a `div_zero` compile error, never a verdict.
- `db.rs:list_history` — listings carry `as_drawn` from the stored view, so the rail shows “Proved (as drawn)”.
- `present.rs:build` — the figure is redrawn by `spread::respread` unless the proof is “as drawn” (its betweenness was read off the engine's figure) or introduces its own points. The engine samples every `triangle` from seed 1 (about 140°/28°/11°), so most textbook figures are redrawn. A refuted figure is redrawn only to an instance where the claim still fails, and its counterexample is measured in the drawn figure (`counterexample(redrawn …)`), so the numbers match the picture.
- `present.rs:counterexample` — `eqangle` with vertex angles (∠ABC) reports the interior angles measured in the drawn figure (`angles`); equal sizes with opposite turn is `angles_oriented`; lines without a common point keep directed values (`line_angles`). `eqratio` gives `ratios`. A metric goal's `values` come from the worst of several sampled figures, so the copy says “in one sampled figure”; a refuted verdict with no counterexample is labelled “Numerical check”. `first_number_after` reads signs and exponents.
- `present.rs:fact_of_pred` — `distseq` (Σ cᵢ·|XᵢYᵢ| = 0) and `distmeq` (Π |XᵢYᵢ|^cᵢ = K) are typeset as `formula` facts (`dist_sum_text`, `dist_product_text`); no engine predicate reaches the page as `raw` in the examples.
- `present.rs:theorem_fact` — every DDAR theorem shows the fact it derives: Menelaus (the product), its converse (collinear), Ceva's converse (`concur`), bisector concurrency (`incenter`/`excenter`, by whether the point lies inside the triangle), the squared-length rules (Pythagoras sums, ⟂, `AB² = q·CD²` and `AB : CD` with q read from the figure), Stewart (t from the figure), law of sines, equal sines, the known sines. `i18n.rs` test `every_ddar_theorem_has_a_romanian_name` reads the theorem names out of the engine sources.
- `present.rs:scaled_relation` — the relation multiplied by `k` is cut after the last `: ` and refused if it still contains a word, so a label never ends up inside the equation.
- `present.rs:source_point_metrics` — `point:` constraints the engine only holds numerically (powers, products, sums, trig) are GIVEN `formula` facts; `caret_powers` turns `^2` in prose into `²`.
- `present.rs:diagnose` — `multiple goals` is `multiple_goals`, located on the second `prove` line. `web.rs:degenerate_goal` only judges a goal that is a single relation call, so `coll(…) ∧ coll(…)` reaches the compiler and is reported as a bad character.
- `render.rs:report_pages_fit` — a report that spills onto a second page first tries figure heights from its own down to `FIG_ONE_PAGE_MIN_H` (150 pt) for a one-page fit (the figure may move beside GIVEN/PROVE on the way), then falls back to the old shrink by the overflow.
- `render.rs:shape_words` — nested line constructors in aux args (`para(I, BA)`, `perp`, `tangent_at`, `isogonal`) and circles are written in words (`aux.line.*`).
- `figure.rs` — marks carry `data-a` (the vertex or midpoint they are drawn around) so the client can scale them; in the label placer construction lines, circles and other points' marks cost 8.
- `spread.rs:aux_rules` — aux points from the search are not rebuilt by the engine (it rejects a `meet`/`point:` whose answer coincides with an existing point, and the search's aux points often do: IMO 2023's A′ is X). Each aux point defined by two loci (`coll` → line, `cyclic` → circle) is recomputed numerically in the new instance, picking the same root as in the engine's figure (`Pick::Same` an existing point, `Pick::Not` the other root's point, or `Pick::Side` of the centre line); other aux points fall back to `point:` constraints. A candidate must keep exactly the original coincidences of aux points.
- `present.rs:helper_points` — every construction-internal point (`_k`) that reaches the page is listed in `View.helpers` with a definition read from the predicates that introduce it (midpoint, reflection, foot, circumcenter, a point on a bisector / perpendicular / parallel / perpendicular bisector, a meet of two lines or circles, a free point). `twins` finds internal points sitting on another point (centroid's midpoint of BC = the user's `Ma`): they keep their own name (the proof is often about the two being equal), get `same` ("the same point as Ma"), have no second dot or label in the figure, and a GIVEN fact about them is dropped when it restates the user's own, else stated with the user's point. App and report list them under "Helper points".
- `present.rs:resolve_branch` — reads the figure to finish an aux sentence: an `excenter` gets its opposite vertex and side (the engine writes all three excenters as `excenter(A,B,C)`); a line–circle `intersect` becomes `intersect2` when a line point is on the circle, else `intersect_near`/`intersect_far`, naming the line point that tells the two meets apart.
- `present.rs` test `every_aux_kind_the_engine_emits_reads_as_words_in_both_languages` reads every `format!("kind(…)")` out of `aux_search.rs`/`aux_virtual.rs` and checks that both server catalogues and both `i18n.js` catalogues have a template, so the raw-text fallback cannot ship.
- `figure.rs:name_markup` / `render.rs:Typeset::name_run` — a name of a capital and one lower-case letter (`Ma`) sets the letter as a subscript `tspan`, the rule of `site.js:nameHtml`; `relabel` reads label names from `data-p`, not the text content.
- `i18n.rs:prose_en` — also gives each theorem one spelling (`angle bisector theorem`, `Menelaus's`, `Thales's`, `Monge–d'Alembert theorem`); `prose_ro` still reads the engine's own spelling.
